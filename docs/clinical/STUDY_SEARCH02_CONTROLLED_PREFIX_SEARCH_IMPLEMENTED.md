It has one entry for each of the 252 active keys, with distinct `canonical_display_name`, `abbreviations`, `equivalent_aliases`, optional `common_display_name`, and `discovery_terms` fields. - `clinical_study_types` still owns active status, IDs, canonical current display, category, and stored aliases. The PHP reader scores **active rows from the database**, then paginates. An inactive study cannot be revived by a search-authority entry. Current database aliases remain searchable even if a later catalog migration adds one before the discovery file is revised; a newly active key falls back to its current display and stored aliases.
- `api/_lib/clinical_study_search.php` is the only scoring implementation. Both the embedded final-leaf composer and the full-catalog/nonembedded composer consume the authenticated `study-types` endpoint. The embedded composer keeps its full active catalog for ordinary FEATURED02 presentation and requests scored pages when the user types. It then intersects server results with the current leaf's eligible key set. “Buscar en todo el catálogo” uses the same server result order without the leaf filter.
- The authority is decoded once per PHP request/process through a static cache. The reader returns `search_authority_version=1` and optional `common_display_name` for each row. Search uses in-memory scoring over the active catalog instead of `LIKE '%query%'`; 252 rows do not require a new index or search service.

## Exact matcher contract

1. Normalize NFKC, Unicode case fold, NFD accent fold, punctuation/hyphen/slash into token boundaries, and repeated whitespace. Keep letters and clinically meaningful digits. Function words `de`, `del`, `en`, and `y` do not constrain prefix matching; the untouched normalized full phrase still receives its exact-match tier. Thus `Cristales en líquido sinovial` and `Cristales en líq` remain discoverable.
2. Default minimum is three normalized characters **per meaningful token**. The fixed short-query allowlist is `t3`, `t4`, `tc`, `ct`, `rm`, `us`, `rx`, `psa t`, `psa l`, `anti cc`, `t4 lib`, `t4 l`, `t3 l`. Any exact canonical, abbreviation, equivalent, or common phrase explicitly present in authority is also allowed with shorter tokens, but only as an **exact configured phrase** match. Thus `BH`, `CA 125`, `CA 19-9`, and canonical names containing `en` work without enabling arbitrary two-letter prefixes. A short modality followed by a qualifying token of at least three characters is allowed, such as `TC de abdomen`. Modality-only exceptions match qualified abbreviations at the approved leading token: `CT` does not match `CTFH`, and `US` does not match `USE` or `PCR-us`.
3. Every query token must prefix a distinct token **within one configured phrase for one study**. Query token order does not matter. No match combines an unrelated alias with a discovery term. No arbitrary infix, edit distance, phonetic guess, stemming, fuzzy model, or auto-selection exists.
4. Tiers, lowest number first: **1** exact canonical display; **2** exact approved abbreviation; **3** exact equivalent alias or stable key; **4** canonical leading-token prefix; **5** equivalent-alias leading-token prefix; **6** all tokens prefixing a canonical, abbreviation or equivalent phrase; **7** common-name match; **8** discovery-term match; **9** stable-key token prefixes. Within a tier, fewer extra phrase tokens, then shorter normalized phrase, then stable key decide order. Pagination follows ranking.
5. A discovery term never becomes a direct alias. `glucosa` and `diabetes` can discover HbA1c at tier 8; `PCR`/`CRP` still show distinct conventional and ultrasensitive CRP studies, and `PCR` can also find the urine protein/creatinine orderable. All choices retain their qualified canonical displays.

## Presentation and navigation

Search rows keep the current canonical display as primary. The 46 configured common displays appear as secondary text only when they add visible information. For example, PSA total/libre show their short names below the full canonical labels; HbA1c does not repeat “Hemoglobina glicosilada” because it is already in the primary label. The accessible add label includes the secondary name once when present. Selected rows retain `✓ Agregado`, cannot be added twice, and the search does not change the clinical dirty state. Clearing search restores the leaf's normal COMUNES/accordion display with the current draft and prepared orders intact. The existing input debounce remains 250 ms.

The boundary is deliberate: a misspelling absent from configured terms can return no result. The physician can use the existing custom-study fallback. SEARCH02 does not change Consultation's separate static study lists.
