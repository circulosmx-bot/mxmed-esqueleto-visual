# STUDY-SEARCH01 — deterministic discovery authority proposal

**AUDIT_ONLY · PROPOSED · DIRECTOR_REVIEW_REQUIRED**

Source HEAD: `7e7c552c59e24ddd2b841e59e676d65a291d8ce4`. This audit snapshots the 252 active `clinical_study_types` rows from the Director review database on 2026-10-04. The [authority matrix](STUDY_SEARCH01_AUTHORITY_MATRIX.csv) has exactly one row per canonical `study_type_key`; the [query expectations](STUDY_SEARCH01_QUERY_EXPECTATIONS.csv) simulate the proposed matcher for 47 queries. Both are **proposals**, not data migrations or runtime behavior. Catalog rows, current aliases, navigation, frontend, backend, schema, writers and readers are unchanged.

## Current read paths and limits

- `api/_lib/clinical_study_catalog_read.php` searches active display, stable key and JSON aliases with escaped SQL `LIKE '%query%'`; results sort by `display_name_es,study_type_id`, not clinical relevance. Accent handling depends on database collation. The endpoint limits each page to 100 and has no token-prefix, term-type or collision model.
- The embedded physician composer in `assets/js/clinical/tax03c-study-composer.js` loads the active catalog, folds NFD accents and case, then uses arbitrary substring matching over joined display, key and aliases. Leaf scope is applied before a local search; “Buscar en todo el catálogo” is its explicit full-catalog escape. It has no semantic ranking. Its nonembedded mode requests the SQL search API in pages of 30.
- The older Consultation study modals in `assets/js/app.js` use separate static search metadata: lowercased accent/punctuation normalization, prefix/contains scores and a two-character minimum for some typeahead lists; their visible-checkbox filter is a separate plain lowercase substring. That is not the canonical 252-study authority. SEARCH02 must scope any integration explicitly and preserve Consultation behavior until separately reviewed.
- The application shell has no single implemented diagnostic-study search shared across every module. Here, “global study search” means the current composer’s explicit full-catalog route, not the patient search or a shell-wide search service.

## Five term types

| Type | Meaning | Exact identity resolution |
| --- | --- | --- |
| `CANONICAL_NAME` | Current `display_name_es` for one active key. | Only if unique. |
| `ALIAS_EQUIVALENT` | Clinically equivalent name for that same orderable and specimen/modality scope. | Eligible after review and collision gate. |
| `ABBREVIATION` | Explicit, scoped acronym or qualified shorthand such as `PSA total`. | Only when exact and unique; an unqualified modality token does not resolve a study. |
| `COMMON_NAME` | Optional secondary physician-facing label, with full study context. | Search/display aid; never changes canonical identity. |
| `DISCOVERY_TERM` | Related condition, analyte or family word that is not a synonym. | Ranking only, always lowest tier and never auto-select. |

The matrix retains **all raw current aliases** in `current_aliases`, while `equivalent_aliases` and `abbreviations` classify those same accepted terms for this audit. `existing_aliases_needing_scope_review` flags broad wording for later review without revoking existing CAT04A/B decisions or current behavior. `proposed_equivalent_aliases` and `proposed_abbreviations` are additions for SEARCH02 consideration only. `expected_leaf` lists every current FEATURED02 leaf for a key; 17 keys appear in multiple leaves, with one canonical identity each.

## Proposed normalization and matcher

1. Apply Unicode NFKC and case folding; remove combining diacritics after NFD. Normalize punctuation, periods, hyphens and slashes to token boundaries, then collapse whitespace. Preserve clinically meaningful letters and digits, especially `T3`, `T4`, `CA 125`, `B12` and specimen qualifiers. Greek-letter forms such as `β-hCG` require an explicit configured term; do not silently equate arbitrary transliterations.
2. Examples: `ant.` → `ant`, `PRO.` → `pro`, `t4-l` → `t4 l`, `anti-CCP` → `anti ccp`. Retain stable-key matching for compatibility, at a tier below exact human-facing terms.
3. Search configured **token starts**, not arbitrary inner substrings. Default minimum is **three normalized characters per query token**. Allow only enumerated exceptions: exact short assay abbreviations `T3`/`T4`; qualified `PSA t`/`PSA l` for total/libre; `anti cc`; `t4 l`/`t3 l` punctuation variants; and scoped modality-only queries `TC`/`CT`, `RM`, `US`, `RX`. Those modality queries search only the leading `TC`/`CT`, `RMN`, `USG` or `RX` token of qualified abbreviations and return choices. Thus `CT` cannot retrieve `CTFH`, and `US` cannot retrieve `USE` or `PCR-us`. A two-character token is never globally enabled by length alone.
4. Use AND semantics: each query token must match a distinct token within **one coherent configured phrase** for the same study. Thus `ant pro`, `pro esp` and `hem gli` can find their intended candidates without combining unrelated fields. Do not use typo distance, stemming, arbitrary substring, opaque ML ranking or clinical defaults.
5. Rank deterministically: (1) exact canonical display; (2) exact approved abbreviation; (3) exact equivalent alias or exact stable key for compatibility; (4) canonical-name leading prefix; (5) equivalent-alias leading prefix; (6) all query tokens matched as prefixes in one phrase; (7) common-name match; (8) discovery-term match. Qualifier specificity, then normalized label and stable key break ties. Pagination must occur **after** matching/ranking so a relevant result cannot be lost in an alphabetic first page. No query automatically orders a study.

The query CSV records the complete proposed ordered key set and tier for each case. The simulation is a design probe, not evidence that the current runtime already returns these results. SEARCH02 must implement and test the matcher independently before these expectations become a gate. Scoped two-letter modality queries in the CSV are proposed navigation behavior, not exact aliases or orderable identities.

| `psa_free` | Current full canonical display and qualified `PSA libre`, `APE libre`, `Antígeno prostático libre`. Suggested common label: `PSA libre`. | `psa l` finds free. | No inferred total/free panel or ratio. |
| `crp_standard`, `crp_hs` | Separate conventional and high-sensitivity CRP studies. | `crp` returns both; `pcr` also meets the existing urine protein/creatinine abbreviation. | `PCR`/`CRP` are proposed discovery words, not unqualified exact aliases. `T3` must show free and total; `VDRL` must show serum and LCR; `LDH` must show serum and body-fluid contexts. `ant`, `pro`, `hem`, `glu` and `eco` are intentionally multi-result prefixes. A display must keep site, specimen, modality and free/total or conventional/ultrasensitive qualifiers visible. In particular, `glu` also reaches the existing GGT alias **Gamaglutamil** through a literal prefix; SEARCH02 should examine that low-relevance hit during ranking QA instead of interpreting `glu` as a glucose-only synonym.

## Family review and conservative additions

- **Laboratory (140 category rows; 152 keys on the laboratory navigation root):** the matrix preserves actual thyroid, hematology, coagulation, chemistry, tumor, cardiac, autoimmunity, infectious, urine/body-fluid and genetics labels. Proposed common expansions are limited to named keys; no panel identity is inferred from a component. [MedlinePlus thyroid](https://medlineplus.gov/ency/article/003444.htm), [liver tests](https://medlineplus.gov/lab-tests/liver-function-tests/), [ANA](https://medlineplus.gov/lab-tests/ana-antinuclear-antibody-test/), [ANCA](https://medlineplus.gov/lab-tests/antineutrophil-cytoplasmic-antibodies-anca-test/) and [blood counts](https://medlineplus.gov/bloodcounttests.html) support the reviewed examples.
- **Imaging (38):** `TC`/`CT`/`TAC` and `RM`/`RMN`/`MRI` must retain anatomy; `US`/`USG`/`ultrasonido`/`ecografía` must retain anatomy and modality. An unqualified modality abbreviation returns choices. Dental cone-beam CT is a distinct orderable from conventional CT. [RadiologyInfo CT](https://www.radiologyinfo.org/es/ctscan), [MR](https://www.radiologyinfo.org/es/info/safety-mr), [ultrasound](https://www.radiologyinfo.org/es/info/breastus), [dental CBCT](https://www.radiologyinfo.org/es/info/dentalconect).
- **Cardiovascular, pulmonary, neurophysiology and sleep (36):** qualified EKG/ECG, Holter, MAPA/ABPM, EEG, EMG/VCN, PFT/PFR and PSG terms remain attached to their exact current test. Generic PFT is discovery-only because complete PFT and spirometry are distinct. [AHA rhythm tests](https://www.heart.org/en/health-topics/arrhythmia/symptoms-diagnosis--monitoring-of-arrhythmia/common-tests-for-arrhythmia), [AHA ABPM statement](https://pmc.ncbi.nlm.nih.gov/articles/PMC11409525/), [MedlinePlus lung tests](https://medlineplus.gov/lab-tests/lung-function-tests/), [MedlinePlus EMG/NCS](https://medlineplus.gov/lab-tests/electromyography-emg-and-nerve-conduction-studies/).
- **Procedures (13):** endoscopy, colonoscopy, bronchoscopy and laryngoscopy retain procedure and organ context. `EGD`/`EDA` is qualified as upper digestive endoscopy; it is not all endoscopy. [MedlinePlus endoscopy](https://www.medlineplus.gov/ency/article/003338.htm).
- **Dental (three DENTAL rows plus dental imaging and cross-listed navigation):** panorámica/ortopantomografía, CBCT/cone beam and cephalometric radiography are separate identities; the FDI location model is untouched. [RadiologyInfo panoramic](https://www.radiologyinfo.org/es/info/panoramic-xray), [NCBI MeSH orthopantomography](https://www.ncbi.nlm.nih.gov/mesh/E01.370.350.700.720.750), [RadiologyInfo CBCT](https://www.radiologyinfo.org/es/info/dentalconect).

Ten studies with broad existing aliases are flagged for scope review in the CSV: `dental_clinical_photographs`, `cma_microarray`, `dental_cbct`, `afp_serum`, `cea_serum`, `cortisol_serum`, `hiv_ag_ac`, `insulin_serum`, `microalbumin` and `tibc`. Some of these aliases were explicitly accepted in CAT04A/B. They remain in the proposed identity-bearing search fields and in current runtime behavior. SEARCH02 would need a separate Director decision and compatibility plan before narrowing any of them.

## Result presentation and SEARCH02 proposal

Show the matched label and the canonical identity together when useful: `HbA1c` with `Hemoglobina glicosilada (HbA1c)`; `PSA total` with `Antígeno prostático específico total`; `PSA libre` with its own full label. For imaging, show modality and anatomy; for lab results, show sample and assay qualifier. Secondary labels are display-only and should never replace `study_type_key` or issued-order snapshots.

**Proposed STUDY-SEARCH02:** add a versioned, reviewable search authority keyed by the 252 active study keys; explicit normalization; controlled token-prefix and multi-token AND matching; deterministic ranking before pagination; optional secondary common-name presentation; exact-alias and abbreviation collision gates; all-study query QA including the 47 cases here and specimen/modality disambiguation; parity checks between embedded and full-catalog search; and a separately approved path for older Consultation modals. Do not change order, result, specimen, routing, provider or historical-document authority merely to improve search. Any current broad alias correction needs a documented compatibility choice.
