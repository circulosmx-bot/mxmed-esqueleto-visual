# OR05-NAVMAP02 — specialty navigation V1 implemented

The physician **Solicitar estudios → Generar nueva orden** screen now uses `assets/js/clinical/or05-specialty-navigation-v1.js` as its version 1 navigation configuration. The complete [NAVMAP01 matrix](OR05_NAVMAP01_SPECIALTY_NAVIGATION_MATRIX_V1_PROPOSED.md) remains the audited source for its 124 finite specialty labels, 10 professional titles, 183 active canonical studies, profile ordering, and proposed study promotions. NAVMAP01 remains labeled *proposed* as the historical audit; this document records the implemented scope.

Four primary navigation groupers remain visible for every profile: LABORATORIO (laboratory, genetics, pathology), IMAGENOLOGÍA (image studies and the six audited cardiovascular imaging keys), ESTUDIOS FUNCIONALES (cardiovascular, neurophysiology, pulmonary function, sleep, audiology), and PROCEDIMIENTOS DIAGNÓSTICOS (endoscopy studies). They are navigation routes over `clinical_study_types`, not new clinical categories. The same study may appear through multiple routes and retains its one canonical `study_type_id` and `study_type_key` when selected.

The initial quick access order comes from the physician's active verified primary specialty credential when its label is recognized, then recognized primary specialty text, then the modeled professional title, then the general profile. Recognized secondary specialties add only unused shortcuts in stored order, up to eight total. Unknown primary text resolves to the title family or general profile. This resolution affects presentation only; it does not grant, prohibit, or change ordering permissions.

The general quick access grid is Cardiología, Neurofisiología, Función pulmonar, Citología, Endoscopía, Sueño, Audiología, and Genética. Other profiles can show zero to eight shortcuts. Runtime category counts suppress destinations with no active studies. In the current catalog, `DENTAL`, `OFTALMOLOGIA`, and `OTROS` have no active studies, so their empty links are hidden; dental profiles receive no artificial filler. `PATOLOGIA` currently has two cervical cytology studies, so the physician-facing shortcut reads **Citología**. **Todos los estudios** remains visible for every profile and opens the full active catalog. Search remains global and retains existing server ordering.

The existing TAX03C composer browses each configured group through the existing paginated category API, using canonical keys for the imaging subset. It deduplicates study IDs across routes. Changing category, choosing **Todas**, or using search permits mixed-category orders. Custom studies and the existing order writer remain available. No schema, clinical reader, writer, result, or provider contract changed.

The matrix's proposed `PROMOTED_STUDY_KEYS` remain in versioned configuration for audit, but study-level promotion is **deferred** in the V1 UI. The current API pages alphabetically by one canonical category at a time. Showing promoted studies first would require reading entire groups or changing server pagination/search ranking. Quick access provides specialty prominence without disturbing that contract.

The source specialty authority remains free text and per-doctor verified credentials, not global specialty IDs. No live profile-frequency evidence was available in the NAVMAP01 review database. Dental, ophthalmology, pathology, urology, and pediatric catalog gaps remain as described in NAVMAP01. V1 does not infer new studies or specialty permissions from those gaps.

Validation: `node modules/clinical/qa/or05_navmap02_config.js` checks all finite labels, canonical keys, group coverage, duplicate and eight-slot bounds, precedence, and fallback. `python3 modules/clinical/qa/or05_navmap02_browser.py` exercises served assets at port 18148 with disposable API fixtures, profile variants, global search, overlap and mixed orders, custom studies, and 1440×900, 1366×768, and 390×844 geometry. Existing OR03, OR04, and TAX03C browser regressions remain part of the QA gate.
